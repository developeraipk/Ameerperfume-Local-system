## 8. HONEST DISCLOSURE OF REMAINING LIMITATIONS & ON-SITE COMMISSIONING

In strict accordance with client handover requirements, the following items cannot be fully signed off in a software-only environment and must be completed physically on-site:

### 1. Physical Hardware Peripherals Attachment
- **Status:** Software drivers, ESC/POS byte generators, Windows Spooler bindings (`winspool.drv`), and COM port polling logic are 100% implemented and unit-tested.
- **Limitation:** Physical 80mm thermal receipt printers (e.g. Epson TM-T88) and 24V RJ11 cash drawers were not physically attached to the development machine.
- **On-Site Action:** During store setup at POS-01 and POS-02, connect USB thermal printers, install standard Windows POS printer drivers, and trigger `Test Print` in the ERP Settings screen.

### 2. Multi-PC Physical LAN Deployment (POS-01 & POS-02)
- **Status:** Local TCP stream synchronization protocol, mutual secret-key authentication handshake, outbox event streaming, and duplicate replay rejection were tested and passed 100% on port 7879.
- **Limitation:** Physical cross-machine synchronization between two physically separate PC chassis connected across a shop Wi-Fi / Ethernet router could not be executed on a single host machine.
- **On-Site Action:**
  1. Install the MSI/EXE package on **Station 1 (POS-01)**. Assign static IP (e.g., `192.168.1.10`). In Settings, set Station ID to `POS-01` and enable LAN Server mode.
  2. Install the MSI/EXE package on **Station 2 (POS-02)**. In Settings, set Station ID to `POS-02` and set Peer Server IP to `192.168.1.10:7879`.
  3. Verify ping and mutual sync status in the Settings screen.

### 3. Production Cloud Backend Deployment
- **Status:** Native Rust HTTP sync client with exponential backoff retry and payload serialization is fully built.
- **Limitation:** The production cloud backend (`http://127.0.0.1:3000` or public cloud endpoint) is currently offline and not hosted on a live cloud domain.
- **On-Site Action:** Deploy the NestJS / PostgreSQL backend to the client's chosen cloud server (e.g., AWS, DigitalOcean, or Railway), configure the HTTPS endpoint and API token in `config.rs` / Settings, and trigger initial push.
